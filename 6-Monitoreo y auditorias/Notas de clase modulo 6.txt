/////////////////// Monitorizar los errores de MSSQL ///////////////////

Es importante saber monitorizar los errores, ya que esto nos permitirá saber si algo esta fallando para poder solucionarlo.
Los errores en SQL Server son objetos en si, lo que nos permite acceder a sus propiedades.
Las propiedades de los errores en SQL Server son:
* Código de error (ERROR_NUMBER)-> Nos indica el codigo del error. Por ejemplo, el error 547 indica una violación de restricción de clave externa.
* Mensaje de error (ERROR_MESSAGE) -> Es un comentario de la causa del error, lo que nos ayudara a identificar el problema.
* Severidad (ERROR_SEVERITY) -> Nos indica que tan grave es el error. Devuelve el nivel de severidad del error (de 0 a 25).
* Origen (ERROR_PROCEDURE) -> Devuelve el nombre del procedimiento almacenado o función donde ocurrió el error.
* Estado (ERROR_STATE) -> Devuelve el estado del error, un número adicional que ayuda a identificar el contexto del error. Útil para depurar, ya que algunos errores tienen múltiples estados que indican diferentes causas.

Estas propiedades pueden recuperarse dentro de un bloque CATCH en una construcción TRY...CATCH
Como ejemplo:
BEGIN TRY
    -- Código que puede causar error
END TRY
BEGIN CATCH
    SELECT 
        ERROR_NUMBER() AS NumeroError,
        ERROR_MESSAGE() AS MensajeError,
        ERROR_PROCEDURE() AS Procedimiento,
        ERROR_SEVERITY() AS Severidad,
        ERROR_STATE() AS Estado;
END CATCH

/////////////////// Configurar correo electrónico ///////////////////

Esto nos sirve principalmente para enviar notificaciones y alertas generadas por eventos en el servidor, como errores, procesos de copias de seguridad, la ejecución de procedimientos almacenados o cualquier otro evento que requiera supervisión.

Para configurar el correo electrónico en SQL Server, debes dirigirte hacia: 'Explorador de objetos > Administración > Correo electrónico de bases de datos (clic derecho) > Configurar correo electrónico de bases de datos'. 
Aquí se nos abrirá una nueva ventana para la configuración del correo.
La primer ventana es para explicar para que sirve el Agente de configuración.
La segunda ventana es para seleccionar la tarea de configuración, si quieres crear un nuevo perfil, administrar cuentas y perfiles ya creados, administrar la seguridad del perfil o cambiar parámetros del sistema.

El la ventana para crear un nuevo perfil, puedes asignarle un nombre, una descripción y con el botón 'Agregar', lo que abrirá otra ventana donde se configuraran los datos de las cuentas SMTP (Protocolo Simple de Transferencia de Correo), como el nombre de la cuenta, la descripción, la dirección de correo, el servidor que usa (dependiendo del proveedor de correo que uses.), etc.

Para revisar si se registro correctamente el correo, puedes ir a: 'Explorador de objetos > Administración > Correo electrónico de bases de datos (clic derecho) > Enviar correo electrónico de prueba', esto abrirá una ventana que te permitirá mandar un correo electrónico desde el correo que se configuro hacia otro correo que especifiques en esta ventana, para corroborar que este configurado de manera correcta.

También puedes ir a: 'Explorador de objetos > Administración > Correo electrónico de bases de datos (clic derecho) >  Ver registro de correo electrónico de bases de datos' para consultar los registros relacionados con el correo electrónico registrado.

/////////////////// Tablas temporales ///////////////////

Son una característica de base de datos que permite mantener un historial completo de los cambios en los datos, facilitando el análisis de los datos en cualquier momento del pasado.
Se compone de dos tablas: una tabla actual que almacena los datos actuales y una tabla de historial que guarda automáticamente las versiones anteriores de cada fila cada vez que se realiza una operación de inserción, actualización o eliminación.

Para que esta característica funcione, la tabla debe incluir dos columnas de tipo datetime2 que se definen como GENERATED ALWAYS AS ROW START y GENERATED ALWAYS AS ROW END  y una cláusula PERIOD FOR SYSTEM_TIME que especifique las columnas de inicio y fin del periodo.
La activación de la versión del sistema se realiza mediante la cláusula SYSTEM_VERSIONING = ON.

Ejemplo:
CREATE TABLE nombre_tabla(
	Id	INT PRIMARY KEY, -- Requiere Primary Key
	SysStartTime DATETIME2 GENERATED ALWAYS AS ROW START NOT NULL,	--Almacena la fecha y hora en que la fila comenzó a ser válida
	SysEndTime	DATETIME2 GENERATED ALWAYS AS ROW END NOT NULL, --Almacena la fecha y hora en que la fila dejó de ser válida
	PERIOD FOR SYSTEM_TIME (SysStartTime, SysEndTime) -- indica las columnas que serán el incido y fin del periodo
)
WITH (SYSTEM_VERSIONING = ON)  -- Se activa el versionamiento

-- Se mostraran todos los datos que han estado en la tabla, inclyendo el momento que empezaron a ser validos (SysStartTime) y cuando dejaron de ser validos por que fueron actualizados o eliminados (SysEndTime)
SELECT * FROM Materias
	FOR SYSTEM_TIME ALL
