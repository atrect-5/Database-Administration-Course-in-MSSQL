/////////////////// Funciones ///////////////////

Es un bloque de código reutilizable que realiza una tarea específica, puede tomar o no datos de entrada, procesarlos y devolver un resultado.

[input] X -> [Función] F: -> [Output] F(x)

Existen diferentes tipos de funciones en SQL Server:
Funciones escalares (de valor único)
	-> Devuelven un solo valor, por ejemplo: la suma de dos números (devuelve solo el resultado)
Table Values (Devuelve una tabla)
	-> Devuelven tablas de resultados de consultas.
Funciones deterministas:
	-> Siempre que se manden los mismos valores como parámetro, retornara el mismo resultado. Por ejemplo, si la función suma 2 números, siempre que se manden los mismos 2 números retornara el mismo resultado.
Funciones no determinísticas:
	-> Puede tener variaciones en la salida aunque se llame con los mismos parámetros. Por ejemplo, funciones basadas en fechas (ya que la fecha va cambiando) o con datos aleatorios.

SQL Server también cuenta con sus propias funciones integradas (built-in):
Funciones de agregación:
	-> Realizan cálculos para retornar un solo valor. Por ejemplo, Count, Max, etc.
Funciones analíticas:
	-> Calculan un valor agregado basado en un grupo de filas (una "ventana" definida por la cláusula OVER). A diferencia de las funciones de agregación, pueden devolver múltiples filas para cada grupo. Ejemplos: LEAD, LAG, FIRST_VALUE, LAST_VALUE.
Funciones de rango:
	-> Devuelven un valor de clasificación para cada fila dentro de una partición de un conjunto de resultados. Ejemplos: ROW_NUMBER, RANK, DENSE_RANK, NTILE.
Funciones escalares:
	-> Operan sobre un solo valor y devuelven un solo valor. Se pueden usar en la mayoría de las partes de una instrucción T-SQL. Ejemplos: GETDATE(), UPPER(), LEN().
Funciones de fila:
	-> Se aplican a cada fila individual de una consulta y devuelven un resultado por cada fila procesada.


Algunas funciones integradas en SQL Server son:
Funciones de Agregación:
    SUM() -> Calcula la suma total de una columna numérica.
    AVG() -> Calcula el promedio de una columna numérica.
    COUNT() -> Cuenta el número de filas en una tabla o resultado de una consulta.
    MAX() -> Devuelve el valor máximo de una columna.
    MIN() -> Devuelve el valor mínimo de una columna.

Funciones Analíticas:
    LEAD() -> Accede a datos de una fila posterior en el mismo conjunto de resultados.
    LAG() -> Accede a datos de una fila anterior en el mismo conjunto de resultados.
    FIRST_VALUE() -> Devuelve el primer valor en un conjunto ordenado de valores dentro de una partición.
    LAST_VALUE() -> Devuelve el último valor en un conjunto ordenado de valores dentro de una partición.

Funciones de Rango:
    ROW_NUMBER() -> Asigna un número secuencial único a cada fila dentro de una partición.
    RANK() -> Asigna un rango a cada fila. Si hay empates en el rango, se salta el siguiente número.
    DENSE_RANK() -> Asigna un rango a cada fila. Si hay empates, no se salta el siguiente número.
    NTILE(N) -> Distribuye las filas en un número especificado (N) de grupos.

Funciones Escalares:
  -> De Cadena:
    UPPER() -> Convierte una cadena a mayúsculas.
    LOWER() -> Convierte una cadena a minúsculas.
    LEN() -> Devuelve la longitud de una cadena.
    CONCAT() -> Une dos o más cadenas en una sola.
    SUBSTRING() -> Extrae una parte de una cadena.
    REPLACE() -> Reemplaza todas las ocurrencias de un texto por otro en una cadena.
    TRIM() -> Elimina espacios en blanco al inicio y al final de una cadena.

  -> De Fecha y Hora:
    GETDATE() -> Devuelve la fecha y hora actuales del sistema.
    DATEDIFF() -> Calcula la diferencia entre dos fechas (en años, meses, días, etc.).
    DATEADD() -> Agrega un intervalo (día, mes, año) a una fecha.
    DATEPART() -> Devuelve una parte específica de una fecha (año, mes, día).

  -> Matemáticas:
    RAND() -> Genera un número aleatorio flotante entre 0 y 1.
    ROUND() -> Redondea un número a una cantidad específica de decimales.
    ABS() -> Devuelve el valor absoluto de un número.

  -> De Sistema y Conversión:
    ISNULL() -> Reemplaza un valor NULL con un valor especificado.
    CAST() -> Convierte un valor de un tipo de dato a otro (estándar de SQL).
    CONVERT() -> Similar a CAST, pero con opciones de formato específicas de SQL Server, especialmente para fechas.

También se permite crear tus propias funciones, (estas pueden también implementar funciones integradas de SQL Server).
Para crear tus propias funciones, debes declararla de la siguiente manera:
/*****Función escalar*****/
CREATE FUNCTION nombre_funcion
( [ {@nombre_parametro [AS] tipo_dato_parametro
	[ = default ]}
	[,...n]
   ]
)
RETURNS tipo_dato_retorno
AS
BEGIN
	cuerpo_funcion
	RETURN expresion_escalar
END [;]

/***** Función ITVF (Inline Table-Valued Function) *****/
NOTA: El resultado que devuelven puede ser tratado como una tabla
CREATE FUNCTION nombre_funcion
( [ {@nombre_parametro [AS] tipo_dato_parametro
	[ = default ]}
	[,...n]
   ]
)
RETURNS table
AS
	RETURN (
		expresion_sql
	)

/***** Función MTVF (multi-statement table valued functions) *****/
CREATE FUNCTION nombre_funcion
( [ {@nombre_parametro [AS] tipo_dato_parametro
	[ = default ]}
	[,...n]
   ]
)
RETURNS @return_variable TABLE
<definicion_tipo_tabla>
AS
BEGIN
	cuerpo_funcion
	RETURN
END [;]


Para eliminar una función, se hace de la siguiente manera:
DROP FUNCTION nombre_funcion 

NOTA: Para actualizar la función es la misma estructura, pero cambiando el inicio de 'CREATE FUNCTION nombre_funcion' -> 'ALTER FUNCTION nombre_funcion'

Puedes ver las funciones que has creado en: 'Explorador de objetos > Bases de datos > tu_base_de_datos > Programación > Funciones'. Aquí vienen las funciones que has creado según su categoría y si das clic derecho, SSMS te creara un archivo base para la creación de una función dependiendo de tipo que escojas.


/////////////////// Triggers ///////////////////

Es un objeto almacenado en una base de datos que se activa automáticamente cuando ocurre un evento específico en una tabla o vista. Los eventos que activan los triggers pueden ser tanto Insert, Update o Delete. No se usa en SELECT, ya que este no cambia el contenido de una base de datos.
La desventaja de los triggers, no son portables, solo puedes usarlos en los motores SQL en donde los creaste.
Se deben usar con cuidado, ya que pueden llegar a consumir todos los recursos del servidor si por un error se activan muchos en cascada, pues suelen consumir muchos recursos.

Existen varios tipos de triggers
DML (Data Manipulation Language) -> Se activan en respuesta a operaciones de manipulación de datos.
	-> Activados por: INSERT, UPDATE, DELETE

DDL (Data Definition Language) -> Responden a eventos que modifican la estructura de la base de datos
	-> Activados por: CRETE, ALTER, DROP, GRANT, DENY, REVOKE

Logon  -> Controlan el acceso al servidor y se activan cuando un usuario inicia sesión. Se activan después de la autenticación exitosa, pero antes de que se establezca la autenticación del usuario.

Existen 2 disparadores para los triggers:
AFTER : Se activa únicamente después de que todas las operaciones especificadas en la sentencia SQL que lo desencadenó se hayan ejecutado correctamente, incluyendo las acciones en cascada de restricciones de clave externa y las comprobaciones de restricciones CHECK.

INSTEAD OF: Anula la acción desencadenante y ejecuta sus propias sentencias en su lugar, lo cual es especialmente útil en vistas para redirigir operaciones hacia las tablas subyacentes.

NOTA: Los disparadores AFTER no pueden definirse sobre vistas, mientras que los INSTEAD OF sí pueden, aunque no se pueden crear sobre vistas definidas con WITH CHECK OPTION

Cuando se activa un trigger se crean la tabla Inserted (donde se almacenan los datos que serán insertados) y deleted (donde se almacenan los datos que serán eliminados). En caso de un UPDATE, Inserted contiene los nuevos datos mientras que deleted contiene los datos antiguos.

Para crearlos, se utiliza esta sintaxis:
CREATE TRIGGER nombre_trigger
ON tabla_objetivo
{ FOR | AFTER }
{ [ INSERT ] [ , ] [ UPDATE ] [ , ] [ DELETE ] }
AS
{
	declaracion_sql
	[,...n]
}

Para eliminar un trigger, se hace de la siguiente manera:
DROP TRIGGER nombre_trigger

NOTA: Para actualizar un trigger es la misma estructura, pero cambiando el inicio de 'CREATE TRIGGER nombre_trigger' -> 'ALTER TRIGGER nombre_trigger'


/////////////////// Procedimientos Almacenados///////////////////

Son un conjunto de instrucciones SQL precompiladas y almacenadas en una base de datos, que puede ejecutarse bajo demanda para realizar tareas específicas como consultas, inserciones, actualizaciones o eliminaciones de datos.

Puede tener parámetros de entrada y salida, parámetros para el bloque, lote o procedimiento que lo mandó a llamar. Puede contener instrucciones sobre bases de datos y ejecutar otros procedimientos almacenados. 
Devuelven un valor de estado (si fue exitosa o no una accion).

También existen tipos de procedimientos almacenados que se definen en T-SQL cuando se crean:
CLR (Common Language Runtime) -> Son creados por los desarrolladores para realizar tareas específicas dentro de una base de datos. Estos procedimientos se almacenan en bases de datos definidas por el usuario. Pueden implementarse utilizando Transact-SQL o como referencias a métodos del CLR de .NET Framework.
	-> Dentro de estos, existen también los temporales, que se que se almacenan en TempDB
De sistema -> Pertenecen a SQL Server y se utilizan para tareas administrativas. Tienen nombres que comienzan con el prefijo "sp_" (stored procedures), se almacenan físicamente en la base de datos Resource y se muestran lógicamente en el esquema sys de cada base de datos.

Para crear un procedimiento almacenado se usa la siguiente sintaxis:
CREATE PROCEDURE/PROC nombre_procedimiento
[ {@nombre_parametro tipo_dato_parametro }
	[ = default_value ]
[ OUT | INPUT ] ] [ ,...n ]
AS
{
	[ ; ] [ ...n ] |
}

Para eliminar un procedimiento almacenado, se hace de la siguiente manera:
DROP PROC nombre_procedimiento

NOTA: Para actualizar un procedimiento almacenado es la misma estructura, pero cambiando el inicio de 'CREATE PROC nombre_procedimiento' -> 'ALTER PROC nombre_procedimiento'


/////////////////// Vistas ///////////////////

 Una vista actúa como una tabla virtual que muestra los resultados de una consulta almacenada, generalmente una declaración SELECT, y no almacena datos propios, sino que recupera información de tablas base o de otras vistas.
 Se puede usar directamente en consultas SQL, como si fuera una tabla real, y es útil para ocultar la lógica compleja de las relaciones entre tablas, así como para mejorar la seguridad al limitar el acceso a ciertos datos.

Para crear una vista se usa la siguiente sintaxis:
CREATE VIEW nombre_vista
AS
setencia_sql

Para eliminar una vista, se hace de la siguiente manera:
DROP VIEW nombre_vista

NOTA: Para actualizar una vista es la misma estructura, pero cambiando el inicio de 'CREATE VIEW nombre_vista' -> 'ALTER VIEW nombre_vista'
